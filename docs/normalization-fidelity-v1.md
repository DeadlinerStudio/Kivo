# 标准化原文保真校验复验（2026-10-19）

**原文覆盖检查显著减少了标准化的漏字错误，但没有解决字段划界。** 同一批新实体测试、相同权重和原阈值下，错误接受从55条降至2条，147条完整正确结果全部保留。仅在dev重新选择阈值后，完整正确199/384，略高于片段模型192/384，但错误接受7/206，高于片段的4/196；目前不能判断标准化路线整体更好。

本轮承接[独立标准化对比](normalization-comparison-v1.md)，保留所有旧权重、旧数据与旧报告，不训练新模型，不根据本轮测试补规则。

## 做了什么

管线为：原句 → 现有小模型复制/重排 → 固定规范句 → 格式规则 + 原文保真校验 → 现有生产KMP时间规则 → 完整或待确认提案。

校验直接使用本次解码产生的复制动作与tokenizer的原文Unicode位置。每个原文字符要么被复制到某个字段，要么属于明确允许删除的片段；不用“输出里出现过相同字符串”冒充位置覆盖，也不读取金标。

- 检查动作合法、字段顺序、结束符、重复复制与重叠位置，并将动作重新渲染，核对真实输出字符串。
- 空格及限定的逗号/分号/冒号可删除；问号、换行及其他未声明内容不会自动忽略。
- “要在/准备在”等只在时间或标题到地点的边界允许删除；“的”只在两个时间片段之间允许删除；请求前缀、备注引导词也限制在各自位置。不通过任意拼接词表来解释缺失文本。
- 不允许丢掉房间号、标题尾字、地点后缀、否定或条件成分。未解释内容产生`source-content-deleted`；动作与字符串不符产生`copy-output-mismatch`。
- 校验不补字、不猜完整实体。失败时保留原文、模型规范句与已抽出字段，要求确认；原提案不再自动接受。

实现见`normalizer_fidelity.py`；独立评估见`fidelity_evaluate.py`。新规则没有搬进生产KMP或客户端。

## 实验隔离

四个既有模型（标准化、片段、同数据BIO、生产v3）权重全部固定。前三者仍共用相同5000条train与360条dev，预测时间走同一个生产Native适配器。未修改训练、神经解码或日期规则。

第三批实体测试在保真策略校准与模型测试前冻结：480条，其中384条可添加、96条需确认；标题/地点和train、dev、前两批测试的完整实体字符串均不重复。增加了带房间号的地点，以及“确认没有录入的成绩”“核实未到账的补助”等包含语义成分的标题。

测试SHA256：`8056dca8061419dbd7ae9a14504637e2ff2f5276d271a441e7d452f4e365799e`。数据仍使用已曝光语法模板，是助手编写的合成实体留出，不是人工审核的真实用户盲测。此时只冻结实体与样本，不宣称新语法隔离。

比较三种标准化设置：原阈值.9、加校验且仍用.9、加校验后仅用dev网格0/.2/.4/.6/.8/.9选阈值。选择目标为观察到的错误接受率≤1%下完整正确最多，同分取高阈值；无可行点时回退并标记不达标。实际dev选择.4：234/288完整正确、1/235错误接受（0.43%）。策略代码SHA、数据SHA、固定权重SHA及dev阈值写入`frozen-protocol.json`后才进行test推理。

## 第三批新实体结果

完整正确要求既有业务字段全部一致且可接受；标题或地点缺字、划错字段都算错误。分母384是应接受样本数，“错误接受率”分母是本路线实际接受数。

| 路线 | 完整正确 / 应接受 | 错误接受 / 已接受 | 96条需确认样本的误接受 |
| --- | ---: | ---: | ---: |
| 标准化原版，阈值.9 | 147/384（38.28%） | 55/202（27.23%） | 1 |
| 标准化 + 校验，固定.9 | 147/384（38.28%） | 2/149（1.34%） | 0 |
| 标准化 + 校验，dev校准.4 | 199/384（51.82%） | 7/206（3.40%） | 0 |
| 固定片段模型 | 192/384（50.00%） | 4/196（2.04%） | 0 |
| 固定同数据BIO | 182/384（47.40%） | 6/188（3.19%） | 2 |
| 原生产v3 | 17/384（4.43%） | 23/40（57.50%） | 5 |

固定.9的配对分析：原版55条错误接受中拦下53条，原来147条正确接受没有损失。额外53条转为待确认；总待确认从278条增加到331条。这个收益来自校验，不能解释为神经模型学会了更正确的标准化。

相对固定.9校验，dev校准.4增加52条正确接受，也增加5条错误接受；274/480仍需确认。**两种校验设置在新测试上都未达到≤1%的错误接受目标**，不能将dev达标写成真实数据质量达标。51.82%也不代表已满足“大模型50%能力”的产品验收：此前约定的是覆盖标题、时间、地点转备注等核心能力，并允许确认，不是这批合成样本上的单一百分比。

不同批次实体难度不同，本次与上一轮45.57%、57.55%不是同一个测试集，不能直接作版本涨跌比较。

## 漏字解决以后，还错在哪里

固定.9剩余两条错误，以及校准.4的七条错误，均通过了原文保真检查，但字段归属不对：

| 原文片段 | 错误划分 | 为什么校验没有拦下 |
| --- | --- | --- |
| 在翠竹社区接待处办理设备报废登记 | 地点“翠竹社区”；标题“接待处办理设备报废登记” | “接待处”没有消失，被放进了错误字段 |
| 今天在听雨学术馆核实未到账的补助，上午7点 | 地点“在”；标题“听雨学术馆核实未到账的补助” | 全部内容被复制，角色归属错误 |
| 晚上8点预约无法启动的电脑维修 | 地点“预约”；标题“无法启动的电脑维修” | 事件动作被当成地点 |
| 今天上午七点核实未到账的补助 | 地点“核实未”；标题“到账的补助” | 文字未丢失，标题语义已变 |

七条中四条涉及“翠竹社区接待处”。片段模型的四条错误也都是该地点被切短、尾部并入标题。这支持一个具体诊断：**陌生复合实体与事件的边界仍是共同短板；把边界输出包装成规范句，并没有消除这项语义判断。** 单批、单seed、七条正确覆盖差距不构成架构胜负证据。

本轮没有根据这些新测试错误追加“接待处”等实体词表，也没有在测试曝光后再改阈值。后续若改角色约束或训练，需要另冻数据。

## 回归、诊断与成本

- 已知16条回归：标准化三种设置均11/12完整正确，4条需确认均未误接受；片段/BIO各9/12，v3为2/12。它们已曝光，单独记账。
- 用户原句在固定`now=2026-10-19T04:00:00Z`、上海时区下，经带校验交互入口实际得到：标题“开会”、时间`2026-10-20T16:00`、备注“地点：逸夫楼”，完整接受。
- 上一轮已曝光的第二批测试作开发重放：原47条错误全部拦下，175条原正确全部保留。这个结果只验证已知失败的修复，不能并入新留出成绩。
- 独立金标复制诊断：dev/test/已知回归共684条正例的正确复制动作均通过保真检查（0条被拦）。它仅检查删除策略与已声明语法兼容，不是模型推理；金标未参与实际模型管线或阈值选择。
- 新增8项行为测试覆盖房间号/标题尾字/地点后缀、否定和条件成分、连接词位置、重复原文、非法动作、Unicode位置和输出不一致。全套50项测试通过，源文件编译检查通过。
- 60条主机CPU测量，校验含额外tokenization的中位耗时0.065ms、样本P95约0.133ms；不含模型、KMP、UI，不是手机数据。它没有消除标准化自回归解码成本；上一轮的标准化与片段主机推理计时仍见原报告。
- 生产单字“十”的日期解析缺陷仍保留，详见[片段原型诊断](core-span-prototype-v1.md)。本轮没有借此放宽日期规则。

完整逐条输出、审计缺口、失败、开发网格和配对ID位于`reports/zh-fidelity-compare-v1`；可版本控制摘要为[evidence/normalization-fidelity-v1.json](evidence/normalization-fidelity-v1.json)。旧报告不覆盖。标准化仍是PyTorch离线原型，无新端侧格式转换、真机或发布结论。

## 复现

```sh
PYTHONPATH=src HF_HUB_OFFLINE=1 TOKENIZERS_PARALLELISM=false \
  ../DeadlinerCore/build/quickadd-env/bin/python -m quickadd_training.normalizer_predict \
  '明天下午 4 点要在逸夫楼开会' --now 2026-10-19T04:00:00Z \
  --fidelity-settings reports/zh-fidelity-compare-v1/prototype.json
```

不加`--fidelity-settings`保留原版入口，便于重现历史结果；校验配置独立于原权重目录，并验证模型、策略和校验源码SHA。评估入口为`fidelity_evaluate`，数据冻结入口为`fidelity_data`，均拒绝覆盖已有实验目录；重跑评估请另指定`--output`。

下一步值得研究的是边界与角色不确定性：提高对陌生复合地点、动作词与标题内部否定的监督，结合角色冲突转确认。当前保留两条候选路线，不据本轮将标准化替换进客户端。父需求的独立人工金标、语言差距及真机正式门禁继续待验收。
