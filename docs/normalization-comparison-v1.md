# 小模型标准化后规则识别：对比 v1（2026-10-19）

本次实际训练并比较了“小模型先标准化，再用规则识别”。**当前候选在已知例子上更完整，在新实体留出集上没有优于直接片段模型；主要问题是标准化漏掉信息后，规则仍能接受格式合法的错误提案。** 这仅评价本轮受约束标准化实现，不足以排除其他归一化模型、更多数据或保真校验后的方案。

## 实验定义

标准化输出固定句式，例如：

```text
原句：明天下午 4 点要在逸夫楼开会
模型输出：时间：明天下午 4 点；事项：开会；地点：逸夫楼
规则结果：开会 / 2026-10-20T16:00 / 地点：逸夫楼
```

这是独立的小型序列模型：同一个 tiny BERT 编码器初始化，加两层128维自回归解码器。输出动作是输入 token 的复制位置，以及 TIME/TITLE/LOCATION/NOTE/CONFIRM/结束等固定格式控制符；不消费直接片段模型的输出，也不在推理时读取答案。复制字段保留原文、固定控制符组装规范句。它学习顺序重排、删除连接成分、角色归位；没有实验自由文本改写或由神经网络计算日期。

规则层只读取模型真正输出的规范句，检查固定字段顺序/重复/缺失，再交给与片段路线相同的生产 KMP 解析 TIME。日期金标和原文金标 spans 不进入推理。这条管线格式受约束、字段值只能来自原文，但仍可能漏复制重要内容。

## 隔离与公平边界

- 标准化、片段、BIO 使用逐字节一致的5000条 train 和360条 dev，编码器 warm-start SHA 相同，seed42、batch24、8 epoch，encoder lr3e-5、新头/解码器 lr5e-4。
- 标准化按 dev 正例规范句完全一致率（90%权重）与负例确认率（10%）选择第6 epoch；片段/BIO 按其事先定义的 dev 片段指标选检查点。新解码器参数较多，损失与选择指标不同；这是同数据/训练预算的方案比较，不能视为严格架构消融。
- 在标准化训练前，新冻结480条比较集，384条正例、96条确认请求。标题与地点和旧 train/dev/test 均不重复；所有路线权重在此次测试前已确定。
- 新集合复用已曝光语法模板，并非新语法盲测或真实用户数据。已知16条回归单独统计。数据来源与 SHA 见 `data/zh-normalization-compare-v1/provenance.json`。
- 标准化置信度仅在 dev 的固定网格0/.2/.4/.6/.8/.9选择，最终为.9。**网格没有任何点达到 <=1% 的已接受错误率目标**；使用预先写好的 correct-10*wrong 回退评分选择候选，不能声称校准达标。

## 新比较集结果

完整正确要求所有业务字段同时匹配且 ready=true。待确认不计完整成功；标题或地点缺字也计错误接受。

| 480条新合成实体留出；384条应接受 | 完整正确 / 应接受 | 已接受错误 / 已接受 | 负例误接受 |
| --- | ---: | ---: | ---: |
| 标准化 → 规则 | 175/384（45.57%） | 47/222（21.17%） | 0/96 |
| 直接片段 | 221/384（57.55%） | 1/222（0.45%） | 0/96 |
| 同数据 BIO | 215/384（55.99%） | 2/217（0.92%） | 0/96 |
| 原 v3 | 30/384（7.81%） | 37/67（55.22%） | 6/96 |

本表使用新实体集，不能与[首轮片段实验](core-span-prototype-v1.md)的63.54%当成同一测试集。标准化的正例规范句完全一致率为64.32%，部分正确规范句因置信度或日期规则被拒绝，因此最终完整覆盖低于这个值。

已知回归中，标准化11/12完整正确、片段9/12、BIO9/12、v3 2/12。用户原句、连续空格、日期与钟点分离、地点名留在标题、标题内部“不/有没有/取消”等例子，标准化均有成功结果。“明天下午4点开会，地点逸夫楼”输出“地点：夫楼”，被置信度门槛要求确认；其余已知确认例也未错误接受。已知例子上的进步没有延伸为新实体集整体进步。

## 错在哪里

实际留出错误：

| 原文内容 | 标准化输出中的内容 | 后果 |
| --- | --- | --- |
| 城西阅览室208 | 城西阅览室 | 房间号丢失，规则仍接受 |
| 办理自行车年检 | 办理自行车年 | 事件标题缺字，规则仍接受 |
| 松林交流中心 | 松林 | 地点被截短，规则仍接受 |
| 竹园讨论室 | 竹园 | 地点尾部丢失，规则仍接受 |

47条错误接受均发生在原本应添加的请求中，主要是字段错误；否定/条件等96条负例此次没有误接受。提高规范格式的合法性只能保证规则可读，不能证明规范句忠实保留了输入。

直接片段路线有原文未解释内容检查；本版标准化路线只有固定格式和置信度检查，没有同等的原文覆盖校验。因此结果同时体现了结构、训练目标和验证策略的差别，不能把21.17%错误率全部归因于“采用标准化”本身。

两个方案共用生产 KMP，均受到现存单字“十”日期解析缺陷影响；详见首轮报告的独立诊断。没有给标准化额外放宽日期规则，也没有根据本次新测试调整阈值或更换检查点。

## 成本与验证

| 主机 PyTorch CPU、3线程、单输入，30条，排除KMP/UI | 标准化 | 直接片段 |
| --- | ---: | ---: |
| 参数量 | 3,761,799 | 3,226,316 |
| 推理中位耗时 | 24.48ms | 2.43ms |
| 本次样本P95 | 64.70ms | 3.23ms |

两者都包含 tokenizer 和各自解码。自回归需要多步解码；当前 Python 解码循环未实现 KV 缓存，因此此项比较的是本轮原型成本，不是优化后端侧实现的性能上限。该测量是桌面 CPU 代理值，不是手机延迟，不包括下载/冷启动/UI。标准化当前只验证了 PyTorch 原型，没有 ONNX/Core ML/MindSpore 或真机部署结论。

训练、真实逐条规范句、四路提案、失败与校准网格在 `artifacts/zh-normalizer-v1` 和 `reports/zh-normalization-compare-v1`。可版本控制的摘要见 [evidence/normalization-comparison-v1.json](evidence/normalization-comparison-v1.json)。规则模块拆分后对856条保存结果重放，字段、标题与备注一致；另有360条金标训练目标→规范文本往返检查，无差异。行为测试累计42项通过，覆盖规范句解析、重复/乱序字段、确认与保留原文等。

共享功能的任务、范围与状态已回写，父需求继续保持未完成。最终全局 `check_feature_index.py` 检查报告另一个并行新增功能 `software-update-design` 尚未登记，汇总数量也因此过期；未改动该无关功能，未宣称全局索引校验通过。本次新增源文件的编译、空白、有效规模及证据 JSON 检查通过。

## 判断与下一轮

本轮继续保留直接片段为较可靠的实验基线；标准化路线保留作候选，不据已知回归的11/12替换当前模型。若继续研究，优先补“每个原文片段是复制还是合法删除”的保真约束，专门处理房间号、地点后缀和事件尾字；再按信息完整性校验对齐两条管线，以新冻结集验证。更长训练或更多样本可能改变结论，本轮单seed实验不作结构上限判断。

## 复现

```sh
PYTHONPATH=src HF_HUB_OFFLINE=1 TOKENIZERS_PARALLELISM=false \
  ../DeadlinerCore/build/quickadd-env/bin/python -m quickadd_training.normalizer_predict \
  '明天下午 4 点要在逸夫楼开会' --now 2026-10-19T04:00:00Z
```

训练入口为 `normalizer_train --allow-synthetic`，四路评估为 `normalizer_evaluate`，新比较集由 `normalizer_data` 冻结。各入口拒绝覆盖已有实验目录；如需重跑请指定新输出路径。生产 v3、客户端与在线清单均未修改，本次不发布权重。
