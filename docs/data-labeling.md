# 人工标注与冻结流程

1. 收集经过授权的真实快速添加文本，移除姓名、地址等个人信息；记录来源和审核者。助手生成文本只作为开发/增强数据，不能冒充真实使用分布。
2. 独立标注完整 proposal。无法确定单一标题、时间、习惯或多任务拆分时标 defer，保留具体原因。不要直接用规则或模型输出作正确答案。
3. 两名审核者独立标注，并对分歧仲裁；尤其检查标题中的时间词、否定/取消到底是操作指令还是待办、循环语义和跨日/跨周边界。
4. 训练样本标注 Unicode 字符 spans。defer 不等于 OTHER：合法但暂不支持的添加请求不能训成非添加类；只有明确非添加请求才能 trainingIntent=OTHER。
5. 为相同表达家族、同义改写、同一标题组合设置同 group，按 group 拆 train/dev/test。工具额外阻止 NFKC 相同文本泄漏。拆分完成后仍需人工复核近似重复。
6. train 用于训练；dev 用于结构、置信度和融合策略选择；test 在候选冻结后仅用于最终验收。记录 test SHA、模型 SHA、清单 SHA 和审核人/时间；已用于调参的 test 应转为 dev，并重建盲测。
7. 根据本项目初始门槛验证完整提案；错误接受率不能只看单字段分类。分别记录纯模型及共享/各端实际融合策略。
8. 三端真机记录设备、系统、冷加载、热推理P50/P95、内存、100+输入、流式输入稳定性、下载失败规则回退和端到端结果。桌面报告只能辅助定位。
