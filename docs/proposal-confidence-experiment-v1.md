# Quick Add 70%覆盖与低错误接受：实验方案 v1

状态：**用户已确认启动；主试验与未完成对照另行记录**。日期：2026-10-19。

当前实证与实现差异见[联合原型报告v3](task-habit-joint-prototype-v3.md)。下文的“拟/待实现/仅设计”保留设计阶段语境，不表示完整实验矩阵或产品门禁已经通过。

本次修订：低于阈值T不单独禁止添加；完整且硬校验通过时可`ready=true、needsAI=true`。本方案将“可添加草案”和“高置信度接受/隐藏AI”分开统计，保留原有70%高置信度完整正确覆盖目标。

加入HABIT后的混合训练矩阵、预算、分类型校准和统计修订见[联合设计v2](task-habit-joint-design-v2.md)。本文22,000条预算及单类型6阈值规则仅为原TASK方案，不代表联合方案仍可沿用相同验证数量。

## 1. 本轮要验证的假设

目标是让≥70%的核心输入被完整、正确地本地接受，同时尽可能不错误接受；可靠时隐藏AI按钮，不可靠时显示。**70%是目标，不是本方案对结果的承诺。**

| 假设 | 验证方式 | 什么结果会否定它 |
| --- | --- | --- |
| 专门训练的整份提案置信度，比请求/token概率更能识别错误 | 固定提取模型，比较原门控与正确性头门控 | 相同错误预算下没有覆盖收益，或高分错误未减少 |
| 陌生实体、边界错位的训练数据是主要短板之一 | 同编码器比较旧权重与扩充数据重训 | 新实体/新表达组没有改善 |
| 整组评分能纠正独立片段选取的边界错位 | 同一提取器、同样候选，比较贪心与组合评分 | 候选内存在正确答案，但选中正确率未提升 |
| 当前BERT容量可能限制提升 | 仅在预定条件触发更大编码器对照 | 增加成本却没有稳定的dev收益 |

## 2. 范围与指标口径

首轮建议支持：中文、单个明确新增TASK、明确且可计算的日期/时间；可含地点、房间号、简单备注。标题、时间、地点/备注须同时正确。地点不必出现，不强制补地点。标点、数字空格、相对日期和跨日历边界纳入正例。

否定新增、条件/二选一、多事件、习惯/复杂周期、只有时间地点而无事件、含糊时间和当前未支持的无截止任务，首轮转确认并纳入保护评估。标题内部“没有/取消/无法/明天”和标题中讨论的地点名不能据关键词一律拒绝。此范围须在采样前审核冻结；不能事后把失败表达移出分母。未覆盖能力另报范围覆盖，不宣称通用中文任务70%。

该70%是本轮中文核心MVP里程碑；父需求历史85%覆盖、语言差距、三格式和真机正式验收继续单独跟踪，不在本文件中悄悄替换。

定义：`P`应接受样本数；`A`为高置信度本地接受数（ready=true且needsAI=false）；`C`为其中完整正确数；`W=A-C`为错误接受/错误隐藏AI数。另设`R`为ready=true可添加草案数、`C_ready`为其中完整正确数、`W_ready=R-C_ready`为可添加但错误的草案数。R包含低置信度草案，不能当作A。

| 指标 | 计算 | 拟定目标 |
| --- | --- | --- |
| 完整正确覆盖率（主指标） | C/P；待确认和部分正确都不算成功 | ≥70% |
| 错误接受率（主风险） | W/A；A=0时不可评估，不能报零风险达标 | 观察值≤0.5%，争取零错误；同时检查置信上界 |
| 保护集误接受 | 应确认输入却ready=true且needsAI=false的条数 | 冻结保护集零条 |
| 错误隐藏AI | 应确认或提案错误时，实际决策却隐藏AI的条数 | 与W一致；后续客户端验收必须核对，不能只看模型离线分数 |
| 可添加草案质量（单独报告） | R/总输入、C_ready/P、W_ready/R；另报ready=true且needsAI=true的数量与错误率 | 不因可添加就计入高置信度成功；没有实际用户操作，不称为“已保存错误” |
| 其他 | 接受精确率、逐字段精确率、部分保留、确认比例、按组指标 | 全量报告，不代替主指标 |

接受不是自动保存。完整且硬校验通过、仅置信度不足的草案可ready=true且needsAI=true，用户可选择添加或调用AI。缺字段/硬失败保持ready=false。客户端提交不能再被needsAI=true一并禁止。风险目标约束的是高置信度接受/错误隐藏AI，低置信度可添加草案的错误风险必须另外披露，不能称为零风险。

保护集同样单列ready=true且needsAI=true的条数、类别与错误草案，审查是否漏过缺字段/硬失败。它们不计为隐藏AI的错误接受，但不能从报告中省略；没有用户实际操作时，不推断用户最终是否会保存。

## 3. 已知基线与提升空间

上一轮第三批合成实体集的历史结果：标准化+保真+dev阈值为199/384完整正确、7/206错误接受；片段为192/384、4/196。数据已曝光，只作回归，不作本轮最终集。

同一保存结果上，要求两条路线都接受且标题/日期/备注一致时共143条，其中3条共同错误。事后看答案、从两份最终草案任选字段正确的一份，只有260/384（67.71%）；这个看答案的诊断不是可部署成绩，也不是全部片段候选的上限。故“投票”或“改阈值”不能替代候选质量提升。

## 4. 数据计划与隔离

以下数量是**建议预算，尚未生成或标注**，合计22,000条源输入。候选扩增不计作新的独立句子。校准两集和最终两集共6,000条须独立人工核验，其中3,000条为最终业务/保护样本；如果尚无这些证据，只能交付合成实验结论，不能写真人70%达标。预算不足可先做合成工程筛选，但不能用它替代这一轮人工验收。

| 分区 | 建议数量 | 唯一用途 | 禁止用途 |
| --- | ---: | --- | --- |
| D_extract | 10,000 | 训练编码器、请求/片段头，含已有train与新增样本 | 校准或验收 |
| D_rank | 2,000 | 在已冻结提取器输出上训练整组排序 | 提取器训练、验收 |
| D_quality | 3,000 | 在已冻结提取器/排序器的实际最佳草案上训练正确性头 | 校准、验收 |
| D_dev | 1,000 | checkpoint、搜索上限、组合/容量对照和最终候选选择 | 校准参数拟合、最终成绩 |
| D_cal_fit | 1,000 | 只拟合已选冠军模型的校准参数a/b | 重新选择模型、选择阈值 |
| D_cal_gate | 2,000 | 只从预定网格选择隐藏阈值T | 训练头、拟合校准器 |
| D_test_business | 2,000 | 最终业务验证：预定1,600正例+400确认输入 | 任何调参、训练或筛选冠军 |
| D_test_protection | 1,000 | 否定/条件、多事件、无事件、歧义等专项保护 | 任何调参、训练 |

这些集合不得只按行随机切分。改写、空格扰动、错位提案、同一来源/模板语义家族必须归在同组；标题/地点完整实体尽量隔离。新表达家族单列标签；业务集常见表达与新家族各占多少在冻结清单中先写明。历史dev/test回归另列，不能混入新最终集。

人工校准/测试需冻结采样说明、原文、gold决策、所有业务字段、独立日期依据、审核/争议裁决记录及SHA。标注者看不到候选模型输出；歧义在模型评估前按统一规则裁决为确认。严禁用生产日期规则的输出直接当日期金标。无真人输入时必须标明“人工编写/审核”，不得称真实用户流量。

所有分区在训练前冻结；D_test两集合封存到最后。D_cal_fit与D_cal_gate正负比例及表达组成尽量匹配预定业务评估混合，保护压力集不能冒充流量分布。若数据预算缩小，必须预先修改版本与统计门槛，不能在结果出来后补数量或换样本以达标。

校准门槛和最终主指标按独立原始请求计数：同一改写/扰动组仅有一个预先指定的代表进入主统计，其余只作分组诊断。表中最终集数量指代表样本，扩增不能补足这些数量；若独立性或分布代表性不足，精确二项上界只能作为模型假设下的诊断，不作为真实流量风险证明。

## 5. 专项样本与训练方法

重点覆盖以下最小对比，变体同组隔离：

| 风险 | 正确与错误的区别 |
| --- | --- |
| 复合地点 | “翠竹社区接待处”不能变成地点“翠竹社区”+标题前缀“接待处” |
| 门牌/楼层 | “柏园阅览室317”“云岭大厦16层”不能漏数字或尾部 |
| 动作与地点 | “预约无法启动的电脑维修”不能把“预约”当地点 |
| 标题内部否定 | “确认没有录入的成绩”是任务；“不要安排查成绩”须确认 |
| 标题内部时间 | “整理明天的培训清单”中的“明天”未必是截止时间 |
| 地点作为讨论对象 | “讨论清晖楼消防方案”不等于在清晖楼讨论 |
| 缺少事件/多事件 | “明天4点在逸夫楼”无事件；多个不同截止时间不强拼单任务 |
| 边界时间 | 跨月/闰日/时区、上午十点、拆开的日期与钟点，含空格变化 |

训练按顺序冻结，避免给校验头喂只在训练集上很漂亮的提取结果：

1. 用D_extract训练提取器；checkpoint只看D_dev；随后冻结编码器与片段头。
2. 在未参与提取器训练的D_rank生成真实候选，训练排序头；离线将每份候选实际组装并经KMP处理，以业务字段全对作为正确排序标签（预测时间可缓存）。每句最多32份组合，有正确候选时用候选softmax排序损失；没有正确候选时记录召回失败，不将“最接近答案”标正确。最后冻结排序器。
3. 在D_quality运行冻结的完整链路，以实际选出的最佳提案与金标是否全对训练二分类正确性头。错误至少一半来自真实模型预测；另加边界移动、漏字、角色互换等训练扰动。若数据不足，报告数量，不用重复扩增冒充独立错误样本。
4. 正确性头可平衡训练正负采样，但校准集恢复预定业务混合。冻结正确性头后只在D_cal_fit拟合校准器，不再联合微调编码器，以保持特征坐标和输出分布一致。

各阶段金标只用于训练/离线评分，运行时只输入原文、上下文、预测候选和规则结果。任何重训编码器、调整排序器/候选数/日期规则，都使旧校准失效，必须从正确性数据生成与校准阶段重做。

在线首轮只给选定最佳组合做日期归一化；若失败，转确认，不自动换第二候选试到能接受为止。未来若加入候选回退，属于选择策略变化，必须重新生成正确性训练样本和校准。

## 6. 对照实验矩阵

| 编号 | 提取/组合 | 接受评分 | 回答的问题 |
| --- | --- | --- | --- |
| B0 | 固定旧片段＋原贪心 | 原请求/片段阈值和硬校验 | 现有参照 |
| B1 | 固定旧标准化＋保真 | 原最小动作概率.9 | 保留路线对照；不能声称同新数据训练的架构对照 |
| E0 | 同B0，不改提取权重 | 新正确性头＋独立校准 | 只改善评分，能减少多少错误隐藏？ |
| E1 | 同尺寸BERT，用D_extract重训，仍贪心 | 新正确性头＋独立校准 | 新监督能否提升候选/完整提案质量？ |
| E2（主线） | **与E1同一提取权重**，增加候选整组排序 | 新正确性头＋独立校准 | 组合评分能否纠正边界归属？ |
| E3（评分消融） | 与E2相同提取与排序 | 单调校准后的原请求概率，不用正确性头 | 专用正确性训练是否比请求概率更有效？ |
| E4（条件触发） | 更大编码器，其余按E2 | 同样的正确性/校准协议 | 编码器容量是否是瓶颈？ |

所有路线共用相同版本KMP和保真/字段硬校验；具体协议不同的复制/片段检查需说明。E1/E2/E3不改变数据预算、tokenizer和提取器权重，E2对E1只增加D_rank组合学习及相应正确性头重训。B0/B1为历史权重参照，不作严格架构消融。

E0保留B0的片段选择方式，仅用新门控替换原请求/置信度软门槛；不能一面加正确性头，一面继续以旧请求阈值将正确草案提前丢弃。原文保真、字段/日期硬失败在所有路线保持生效。E3中原请求logit也只作为待校准的消融分数，不将其未经验证命名为提案正确概率。

主线与数据重训采用seed42/43/44，报告dev均值/离散与每个seed。可先用42做开发，但不能把其结果表述为三seed结论。冠军只在D_dev上按“经验错误接受≤0.5%时覆盖最高→错误更少→主机耗时更低”的固定顺序选择，冻结单一模型后才启用D_cal_fit和D_cal_gate；最终主验收只针对该冠军。预登记B0/B1在同一最终集重跑作参照，其余路线只比较dev；不能根据最终结果改选冠军或seed。

E4仅当D_dev的正确候选召回不足85%，或E2在dev无任何设置达到70%覆盖且经验错误接受≤0.5%时触发；仍在最终测试前完成。E4候选规格为4层256维，并须确认可用中文预训练初始化与转换算子。若更换预训练来源，须披露来源差异，不能归因于层数单一因素。

## 7. 校准与隐藏阈值

正确性原始logit不是业务概率。首轮预定单调Platt校准：`c=sigmoid(a*z+b), a>0`，只在D_cal_fit最小化未重加权NLL。输出Brier、NLL、10个等宽置信区间的校准图，以及高分段的实际全字段正确率；这些是诊断，不能单靠ECE低就宣布安全。

阈值网格固定为：**0.90、0.95、0.98、0.99、0.995、0.999**。在D_cal_gate中，每个阈值都执行真实KMP、硬校验和完整提案决策，然后统计C/P和W/A。

拟定选取规则：

1. 候选须C/P≥70%；且错误接受率的**单侧上置信界≤0.5%**。
2. 用精确二项分布上界；因同一集合搜索6个阈值，每档采用`alpha=0.05/6`，对阈值搜索做保守校正。
3. 可行候选中选完整正确覆盖最高者；同分选更高阈值。没有可行阈值就记本轮失败，不回退到“正确数减若干错误数”的宽松评分。
4. 固定模型、校准器、阈值、策略、日期版本和所有SHA后，才打开最终测试。90%失败时不能坚持隐藏90%以上所有结果。

二项上界要求样本有足够独立性；同句扰动不能当多个独立证据。零错误也需要足量已接受样本：单个固定阈值下，600个接受结果零错误的单侧95%上界约0.498%；搜索6档时，1,000个接受结果零错误的校正后上界约0.478%。少量样本零错误只能报“观察到零”，不能据此宣称风险足够低。

## 8. 最终验收与失败处理

| 验证 | 通过要求 | 不通过时 |
| --- | --- | --- |
| 冻结业务集 | 完整正确覆盖≥70%；错误接受观察值及单侧95%上界均≤0.5% | 保留现有实验候选，报告未达目标 |
| 冻结保护集 | 零错误接受，按否定/多事件/无事件等分组列数 | 记录具体错误；修订后另冻下一轮测试 |
| 信息完整性 | 接受结果不漏房间号/标题尾字，不将角色错位当正确 | 计错误接受，不做部分得分冲抵 |
| 决策行为 | 完整且硬校验通过但低于T：ready=true/needsAI=true且可添加；硬失败：ready=false/needsAI=true；空输入两者false；旧异步结果不覆盖 | 修复门控及提交条件，重新做相应验证，不直接发布 |
| 再现与产物 | 模型/数据/校准/规则指纹一致，逐条可重放 | 不出达标结论 |

最终测试阈值已固定，只检验一个冠军，不再按6阈值选优；业务集与保护集分开判定，不能合并稀释错误。单侧上界针对冻结混合下的样本风险，不保证分布变化后的真实用户零错误。父需求正式验收另行进行。

最终失败可以分析，但一旦据此修改模型、规则或阈值，原测试即转开发证据。重新冻结新集后才做下一次验收；不能在同一个最终集反复修到通过。

候选诊断必须区分“正确片段根本没进池”“组合池没有正确提案”“有正确候选但排序选错”“提案正确但未达到隐藏门槛”“错误提案却高置信度通过”。还要单列“低置信度且可添加”的正确与错误草案。需要看答案的oracle诊断只用于定位，不计实际覆盖。
